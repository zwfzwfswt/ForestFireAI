# ForestFireAI 开发路线

状态：分阶段实施建议 v0.1，无日历工期承诺；需按团队、设备、数据和试点范围估算。本文不会触发依赖安装、代码修改或部署。

范围依据 [产品需求](01-product-requirements.md)，落实时同时检查 [系统架构](02-system-architecture.md)、[数据库](03-database-design.md)、[API](04-api-design.md)、[UI](05-ui-design.md) 和 [AGENTS.md](../AGENTS.md)。

## 1. 交付原则

每个开发任务完成一个主要功能及其必要测试，先分析相关实现再修改。一个阶段包含多个小任务，不把整阶段作为一次大重构。现有正常功能保持可用；模板演示和品牌清理只在明确授权的任务内进行。

先建立契约和受控数据闭环，再接真实设备和算法。测试环境不得向真实设备发送控制。文档中的性能数值是试点目标，阶段验收必须记录测量条件和结果。

## 2. 分阶段计划

| 阶段 | 可独立拆分的主要任务 | 前置条件 | 出口标准 |
| --- | --- | --- | --- |
| S0 基线与契约 | 当前构建/类型基线；权限和缓存专项核对；测试基础；确定身份兼容方案和字段枚举 | 六份文档评审 | 保留页面清单、可执行测试入口、Mock/接口契约、已知基线问题记录 |
| S1 后端与 GIS 基础 | FastAPI 最小服务；身份/菜单兼容；首批迁移；林区查询；Leaflet 容器；图层展示 | S0，底图与坐标约定 | 登录/权限不退化，授权林区地图可用，数据库迁移可验证 |
| S2 告警与事件闭环 | Media 图片上传；Fire Alert 人工录入/认领/复核；Fire Event 状态/时间线；基础 Weather/资源台账；Dashboard 聚合 | S1 | 人工证据 → 告警 → 事件 → 处置归档完整可追溯，重复复核不产生重复事件 |
| S3 无人机仿真闭环 | UAV 台账；Telemetry 接入/回放；WS 恢复；Mission 航线/任务；命令申请与人工确认；SITL 网关 | S2，仿真飞控可用 | 仿真任务执行、失联/未知回执处理、重复命令防护均通过 |
| S4 AI 与媒体增强 | 模型版本注册；异步推理；检测到告警；视频接入；验证集评价 | S2 的媒体/告警，GPU/模型条件 | 输入和模型版本可追溯，结果可复核，明确误报/漏报表现，不把演示指标当实测 |
| S5 多源分析与调度 | Remote Sensing 目录/处理/发布；Weather 供应商适配；Emergency Resource 并发分配；Decision Support 规则方案 | S2，数据源和资源规则确定 | 产品可叠加、气象时效可见、资源不超分、方案带输入依据且人工批准 |
| S6 LLM 辅助 | 授权知识库；LLM Copilot 会话/引用；事件报告与方案草稿 | S5 数据质量与权限闭环 | 引用可验证、越权检索被拒绝、无控制工具、无依据时明确说明 |
| S7 试点与运行 | 真实设备受控接入；容量压测；Docker/Nginx 配置；恢复演练；操作培训 | S3 控制验收，按试点范围选 S4/S5/S6 | 现场人员认可流程、备份可恢复、观察指标达标、回退方案可执行 |

S4 与 S5 在数据契约稳定后可以由团队独立推进；S6 不阻塞基础监测上线。这是工作依赖说明，不要求自动启动并行代理。

## 3. 十三个模块的阶段覆盖

| 模块 | 首次交付 | 后续增强 | 关键依赖 |
| --- | --- | --- | --- |
| GIS | S1 林区和基础地图 | S3 轨迹；S5 遥感与资源叠加 | 坐标/图层服务 |
| UAV | S3 设备台账和仿真控制 | S7 真实设备适配 | 设备能力与人工确认 |
| Telemetry | S3 最新状态与历史回放 | S7 高频容量优化 | MQTT、时序分区、WS |
| Mission | S3 航线版本与任务 | S7 现场复核流程 | UAV、控制回执 |
| Media | S2 图片资产和证据 | S4 视频/热红外 | MinIO、访问授权 |
| Fire Event | S2 状态和时间线 | S5 资源/方案关联 | 告警复核与权限 |
| Fire Alert | S2 人工告警和复核 | S4 AI；S5 遥感来源 | 幂等与位置核实 |
| AI | S4 推理与检测 | 评价结果驱动模型更新 | Media、Worker、标注样本 |
| Remote Sensing | S5 影像与产品 | 后续多时相分析 | 数据授权、GDAL/Rasterio、GeoServer |
| Weather | S2 受控观测数据 | S5 实际观测/预报供应商 | 数据来源/时间/单位 |
| Emergency Resource | S2 台账 | S5 预留/派遣/释放 | 区域权限、并发事务 |
| Decision Support | S5 规则方案 | 后续传播模型/情景比较 | 事件、天气、资源、产品 |
| LLM Copilot | S6 引用问答和报告草稿 | 后续更丰富授权知识 | 可追溯数据、模型部署选择 |

S2 的受控数据必须在环境及 UI 中明确标记为测试数据。任务规划中的算法、供应商和硬件选型只在对应任务确定，不一次性安装整套长期技术栈。

## 4. 推荐首批任务粒度

1. 建立当前前端类型/构建基线并记录已有失败，不混入业务改动。
2. 引入最小业务测试基础，完成响应壳或权限边界的一项有效测试。
3. 明确自有身份服务或兼容网关方案，完成登录、用户信息、菜单契约测试。
4. 创建空间基础迁移及林区查询接口，测试跨区域权限和几何有效性。
5. 创建可复用 Leaflet 容器，验证尺寸变化、销毁和无数据状态。
6. 创建 GIS 动态菜单与林区图层页，完成列表/地图联动。
7. 实现图片证据上传与访问授权。
8. 实现一条告警的人工复核事务及事件关联。

每一步仅在用户授权编码后实施。首批任务不包含自动删除 demo、重命名整个仓库或搬迁前端目录。

## 5. 测试计划

当前只有 type-check/build 等脚本，没有业务测试脚本。前端计划评估 Vitest + Vue Test Utils，浏览器关键流程评估 Playwright；后端计划 pytest 和真实 PostgreSQL/PostGIS 集成测试。具体版本与依赖由对应测试基础任务确定，不在本次安装。

| 范围 | 必须验证 |
| --- | --- |
| 兼容基线 | 登录刷新、菜单转换、系统页面 API、分页响应壳、退出清理 |
| GIS | 经纬度顺序、合法 geometry、视野筛选、图层权限、尺寸与内存清理 |
| Fire Alert/Event | 并发复核、重复请求、状态拒绝、重复告警关联、时间线完整性 |
| UAV/Mission | 未确认/过期/改参拒绝；单次确认；网关掉线；UNKNOWN 不重发；ACK 与完成区分 |
| Telemetry | 重启会话、乱序、重复、过期、跨分区去重、断线快照和 cursor 恢复 |
| Media | 分片完整性、私有对象、签名过期、禁止越权和 Token 外泄 |
| AI/Remote Sensing | 可追溯输入版本、失败重试、取消、阈值、缺定位、坏影像与未发布产品 |
| Weather/Resource | 预报/观测时间、缺测值、单位、并发占用和释放幂等 |
| Decision/LLM | 过时快照、审批版本、来源引用、跨用户检索隔离、控制工具不可达 |
| 运行 | Nginx WS/SSE、负载与积压、数据库/对象存储恢复、设备仿真隔离 |

代码变更运行相关测试和前端类型检查；涉及构建、路由、依赖时运行 build。数据库迁移使用真实 PostGIS 测试，不能仅用 SQLite 替代空间约束验证。飞控相关验证使用仿真，实机测试必须独立授权与现场人工确认。

## 6. 阶段风险与决策点

- 身份兼容：旧接口字段存在 string/number 混用；S0 冻结契约，在后端边界转换。
- 存储容量：原始遥测增长快；S3 验证分区和清理，再决定采样频率与留存。
- 地图与影像：服务授权、投影、GeoServer 发布适配决定展示方式；S1/S5 使用已知样例验证。
- 飞控差异：不同设备对命令幂等和回执支持不同；S3 建能力矩阵，S7 不通用化猜测结果。
- AI 效果：最终质量依赖代表性样本；S4 冻结评价集后给出测量结果和适用范围。
- LLM：模型来源与部署方式待定；S6 可只交付受控检索及草稿，不能降低人工确认要求。

## 7. 完成定义与报告

每个任务必须有明确主功能、相关文件范围、权限和接口定义、可执行验证、已知限制。核心功能不得以“页面能打开”替代业务测试；不满足前置条件时报告未验证项。

交付报告固定包含：修改文件、实现内容、测试结果、剩余问题。不得自动 git commit 或 git push。文档任务仅运行内容、链接、格式检查；本轮六份文档不要求运行业务构建或测试。
