# ForestFireAI 产品需求

版本：设计草案 v0.1。本文描述目标产品，不表示功能已经实现。

项目中文名称：基于AI和无人机的森林防火智能监测预警与决策支持系统。

相关文档：[系统架构](02-system-architecture.md)、[数据库设计](03-database-design.md)、[API 设计](04-api-design.md)、[UI 设计](05-ui-design.md)、[开发路线](06-development-roadmap.md)。开发约束见 [AGENTS.md](../AGENTS.md)。

## 1. 现状与产品目标

当前仓库是源自 vue3-element-admin 的 Vue 3 管理前端，已有认证、动态菜单、角色权限、字典、通知、SSE、Pinia、四种布局及 ECharts。Dashboard 混合使用接口数据与模板演示数据；尚无森林业务后端、地图或无人机接入。

目标是形成“采集 → 检测 → 告警 → 人工核实 → 火情处置 → 复盘”的可追溯闭环。GIS 统一呈现空间态势；AI 提供检测能力；Decision Support 生成可解释方案；LLM Copilot 提供信息检索和建议草稿。

首版范围假设：单机构部署、多个林区、PC 值班工作台，先使用仿真设备和受控样例数据。多租户作为可选能力预留，真实设备型号、影像/气象供应商和容量需在接入前确认。

不纳入首版：自动灭火、无人审核自主飞行、完整飞控替代、全自动应急指挥、三维数字孪生、大规模模型训练平台。现有正常模板功能未经明确要求不删除。

## 2. 用户和权限

| 用户 | 主要职责 | 权限边界 |
| --- | --- | --- |
| 值班监测员 | 查看地图、查看证据、复核告警 | 不能默认获得飞行控制权限 |
| 飞手 | 核对设备、规划任务、确认控制操作 | 仅控制授权设备和批准任务 |
| 调度指挥员 | 接管火情、分派人员资源、审批方案 | 所有派遣有记录；飞行仍需飞手确认 |
| GIS/遥感分析员 | 管理图层、处理影像、发布产品 | 数据发布与任务执行分权 |
| AI 运维员 | 管理模型、阈值、推理任务 | 不能替代火情人工核实 |
| 系统管理员 | 用户、角色、组织、配置、审计 | 管理权限不视为一次飞行操作的人工确认 |
| 只读观察员 | 查看授权态势、报表 | 无状态修改和控制权限 |

沿用 roles/perms 和动态菜单，新增林区、设备及资源范围校验。后端必须对列表、详情、文件、实时订阅和操作统一鉴权。

## 3. 模块需求与验收

P0 为最小业务闭环，P1 为接入和业务增强，P2 为后续分析能力；同一模块可分阶段交付。

| 编号 / 模块 | 职责和输入输出 | 首要验收标准 | 优先级 |
| --- | --- | --- | --- |
| FR-01 GIS | 林区边界、图层、空间查询；叠加业务对象 | 按视野加载，点击对象打开详情，切换布局地图不空白 | P0 |
| FR-02 UAV | 设备身份、能力、健康和控制网关 | 展示授权设备；禁用/离线设备不能被正常派发任务 | P0 只读，P1 控制 |
| FR-03 Telemetry | 接收遥测、最新状态、轨迹回放 | 乱序不覆盖较新状态；显示采集时间与过期标记 | P0 仿真，P1 实机 |
| FR-04 Mission | 航线版本、巡检/复核任务、执行记录 | 草稿可修改；执行版本冻结；未经确认不下发 | P0 草稿，P1 执行 |
| FR-05 Media | 图像、视频、热红外资产及证据 | 上传可查验，关联采集任务和时间，过期链接可重取 | P0 图片，P1 视频 |
| FR-06 Fire Event | 已确认火情的处置主记录 | 多条告警可归一事件，状态流转和资源使用可追溯 | P0 |
| FR-07 Fire Alert | 多源疑似异常的规则触发、去重与复核 | 确认时创建/关联事件；误报、重复必须有理由 | P0 |
| FR-08 AI | 模型版本、推理任务、检测结果 | 保留模型、输入、置信度和定位来源，失败可重试 | P0 样例，P1 推理 |
| FR-09 Remote Sensing | 影像目录、处理作业、产品发布 | 可按范围时间筛选，结果以图层展示并记录数据血缘 | P1 |
| FR-10 Weather | 气象观测、预报和质量状态 | 区分观测与预报，保留发布时间、有效时间及单位 | P0 只读，P1 服务 |
| FR-11 Emergency Resource | 人员、队伍、车辆、水源和装备 | 按位置能力查询；并发分配不超额、不重复占用 | P0 台账，P1 分配 |
| FR-12 Decision Support | 汇总火情、气象、地形和资源生成候选方案 | 说明输入时效、依据、限制与方案版本；人工审批 | P1 规则，P2 模拟 |
| FR-13 LLM Copilot | 授权检索、解释、报告和方案草拟 | 回答包含可定位来源；越权资料不可检索；不执行控制 | P2 |

模块边界：UAV 管设备，Telemetry 管状态流，Mission 管任务与航线，Media 管文件证据。Fire Alert 是线索，Fire Event 是经过核实的处置对象。Decision Support 管结构化方案，LLM Copilot 是辅助交互入口，不拥有控制命令执行能力。

## 4. 核心流程与状态

### 4.1 告警到火情

采集影像/人工报告/遥感异常 → AI 或规则生成 Fire Alert → 值班员查看证据 → 确认新建 Fire Event 或关联已有事件 → 指挥员分派任务/资源 → 处置与归档。

- 告警状态：`NEW → REVIEWING → CONFIRMED | DISMISSED | DUPLICATE`。
- `CONFIRMED` 必须关联事件；`DISMISSED` 记录误报理由；`DUPLICATE` 指向重复的告警原件。重复记录不物理删除。
- 火情状态：`CONFIRMED → DISPATCHED → RESPONDING → CONTROLLED → CLOSED`。
- `CLOSED → RESPONDING` 仅允许授权人员带理由重开。
- 新建事件和确认告警在同一事务内完成。并发复核冲突返回最新版本，不默默覆盖。
- 无法定位的检测可进入待定位告警，不能伪造坐标；创建正式事件前补齐已核实位置。
- 严重程度与状态独立：`LOW | MEDIUM | HIGH | CRITICAL` 是初始产品枚举，不宣称等同任何外部法定分级标准。

### 4.2 任务和无人机控制

任务状态：`DRAFT → READY → EXECUTING → COMPLETED | FAILED | CANCELLED`。READY 表示任务可申请执行，不表示已经下发。取消正在执行的任务也属于控制操作。

飞手查看冻结的任务/航线版本、设备、参数和当前遥测 → 创建控制请求 → 人工确认 → 网关下发 → 等待设备回执 → 核对执行状态。

命令状态：`PENDING_CONFIRMATION → CONFIRMED → SENT → ACKNOWLEDGED → SUCCEEDED | FAILED`；确认过期为 `EXPIRED`，下发或回执不明为 `UNKNOWN`。UNKNOWN 不自动重发，先查询设备实际状态。设备已接受命令不等于任务已完成。

### 4.3 决策辅助

事件和数据快照 → 规则/分析作业 → 候选方案 `DRAFT` → 人工 `APPROVED | REJECTED`。批准方案不自动下发飞行命令或分配资源；用户在对应业务模块再次执行授权动作。输入发生关键变化时方案标为过时并重新计算。

## 5. 非功能需求和容量假设

以下是初始验收目标，须在约定硬件、数据量和网络下压测，不是当前实测结果。

| 项目 | 初始目标 / 验证方式 |
| --- | --- |
| 试点规模 | 20 台设备、每台 1 Hz 归一遥测、20 个并发浏览器；视频单独测量 |
| 页面与 API | 内网普通分页查询 P95 ≤ 1 秒；首屏业务数据可交互 ≤ 3 秒，外部底图加载单独记录 |
| 遥测时延 | 从网关接收至 UI 更新 P95 ≤ 2 秒；10 秒未更新标为过期，阈值可配置 |
| 告警到达 | 从服务端创建告警至授权客户端可见 P95 ≤ 3 秒，不包括模型推理时间 |
| 断线恢复 | 网络恢复后 10 秒内发起恢复；超出重放窗口主动拉快照，无静默漏警 |
| 数据完整性 | 重复消息、重复请求不重复创建业务记录；事件状态和命令都有审计 |
| 安全边界 | 越权 HTTP/WS/文件访问被拒绝；控制必须人工确认；密钥不进入前端 |
| 可恢复性 | 试点目标 RPO ≤ 24 小时、RTO ≤ 4 小时；上线前完成备份恢复演练 |
| 可访问性 | 严重程度同时使用文字、图标和颜色；支持键盘操作和暗色主题 |

20 台设备以 1 Hz 持久化一天约 172.8 万条遥测，存储设计需按此量级评估。高频原始数据留存和抽样策略见数据库文档。

## 6. 待确认事项

- 试点区域与林区边界来源、底图服务和坐标要求。
- 设备/机巢/相机型号、飞控协议支持范围和遥测频率。
- 天气与遥感供应商、授权、更新周期、离线部署要求。
- 告警阈值、严重程度定义、复核与处置时限的业务认可。
- 样本标注、模型评价集、可接受漏报/误报指标及 GPU 条件。
- 数据留存、视频并发、实际恢复目标和组织权限范围。

这些选择影响后续接入和验收，不阻碍先实现受控数据下的 P0 闭环。
